## Enumeration and restrictions

DeckLinkBridge enumerates every device exposed by the installed driver, including inactive/input-only logical outputs. SDK model name and DeviceGroupID distinguish physical cards; display name and subdevice index identify logical outputs. If physical grouping is unavailable, endpoints remain explicitly ungrouped and pairing is disallowed; slot numbers or cable positions are never guessed. Driver logical outputs are not necessarily a one-to-one map of every physical BNC jack, especially across card profiles. The app does not switch Desktop Video profiles or activate hidden connectors.

GetDisplayModeIterator + DoesSupportVideoMode enumerates actual SDI modes supported for the BGRA or YUV8 formats this adapter handles, with SDK mode IDs, dimensions, scan type and exact rational frame rate. This is not an inventory of every possible pixel format/connection type. The Swift HardwareInventory exposes all of these and separately identifies the app-supported progressive1920×1080 subset. Pair mode lists intersect SDK ID, dimensions, scan and rational timing and require same-card synchronization support. Self-pairing and duplicate-use are blocked. Driver capability support does not prove an output is currently free; hardware start retains native preflight and enable-failure handling.

Discovery rescans at launch, Rescan, Apply and start. Bounded retries handle changing count/capabilities; saved assignments are never silently rewritten. Missing hardware remains diagnosed with a removal/repair path. No continuous hot-plug notification subscription exists. Up to16 destination assignments /32 endpoints; inventory is not limited to a specific card count. Four-card operation has offline coverage but has not been tested on four physical cards.

The scheduler now uses120000 ticks/second, so23.976 uses5005 ticks exactly. The old preview2502/60000 duration rounded this rate. All other durations doubled, preserving physical50/59.94 timing. Raw duration numbers are not persisted in roomProfiles.v1, so this requires no profile-schema migration.
